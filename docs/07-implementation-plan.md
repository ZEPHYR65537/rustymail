# 实现计划与验收矩阵

## 1. 当前状态与推进原则

2026-09-21：设计文档已先提交，Rust 实现推进至 0.2.0。已有环回 SMTP、原文存储、本地原子接受、事务迁移、离线 GC、操作查询与缺失正文恢复，见[第一轮教程](10-first-implementation.md)、[M1 教程](11-m1-storage.md)与[M1 验证报告](../reports/m1/validation.md)。尚无生产发布包；提前运行的 SMTP 子集仅用于存储验收，不代表完成依赖 M2 的 M3。

阶段完成的含义是：代码、测试、教程、运维接口和验证证据同时满足退出条件。M1 的本地存储范围已完成，Linux ext4/QEMU 故障模型与性能基线有原始证据；这不等于生产发布，也不替代物理存储栈验收。M0 仍有待补项，M2–M8 尚未完成，局部完成状态逐条记录。

单人参考工作量约 20–36 人周：协议互通与故障验证存在较大不确定性，不能用该估计承诺日期。获得第一个实验收发闭环可以更早，但不等于生产发布。

## 5. 测试层次与证据

纯状态机用单元和 property tests，framing/codec 用 fuzz，存储用真实文件系统与故障注入，协议用独立客户端和假对端，生产行为用 Linux VM。参考服务器可用于互通对照，但不能因为行为相同就忽略规范差异。

每个 bug 先保存最小失败输入，再写回归测试；不堆只重复实现细节的测试。PR 必须说明破坏了哪个不变量、修复后的行为和验证方式。CI 基本门槛是 format、Clippy、测试、迁移兼容性、依赖检查；慢故障/压力测试定期运行并在发布前完成。

完整生产证据结构（当前已有 `reports/0.1.0-lab` 的实验验证和依赖清单）：

```text
reports/<release>/
  environment.md        硬件、OS、磁盘、依赖版本与配置
  protocol-matrix.md    条款/场景对应测试名与结果
  durability.md         进程终止与 VM 断电的故障点结果
  interoperability.md   Gnus、第二客户端、外部服务和测试账号范围
  performance.json      原始负载指标与运行命令
  restore-drill.md      恢复过程、RPO/RTO、校验摘要
  security-review.md    已关闭/尚未关闭的问题与影响
  limitations.md        当前容量、协议和部署限制
```

不要创建空报告后宣称检查已通过。当前真正执行的检查只记在[验证记录](validation.md)。

- [ ] M0–M7 全部退出条件满足；必选 SMTP/IMAP 行为有独立互通证据。
- [ ] 进程异常退出、系统掉电、磁盘满、提交结果未知的测试全部通过。

- [ ] 性能报告同时披露主服务与依赖总资源、未满足目标和已知限制。
- [ ] 非作者视角完成一次安全/可靠性评审；关键问题修复后复测。
- [ ] 完成小规模真实邮件灰度、监控告警与值守安排。

## 7. L2 完整目标门槛

在 L1 基础上：M8 完成；直接 MX 路由、Null MX、失败分类、MTA-STS、DNS/SSRF、TLS 兼容策略均验证；至少两个独立外部服务双向互通；PTR、DKIM、SPF、DMARC 实际通过；队列积压、IP 信誉和政策拒绝有真实运维路径。

低信誉 IP、供应商封端口或域策略不匹配会影响投递，不能由软件质量声明覆盖。保留经过验证的中继作为管理员主动切换选项，绝不自动改变信任或加密政策。

## 8. 风险登记

| 风险 | 早期验证 | 失败时的处理 |
| --- | --- | --- |
| IMAP 完整实现工期被低估 | M0 literal spike，M5 条款矩阵 | 缩减可选扩展，不能冒充 rev1 核心已完整 |
| 磁盘同步决定吞吐上限 | M1 测 fsync 与混合读写 | 优化索引/小批提交或升级磁盘，不牺牲耐久性 |
| MIME 库分配不可控 | M0 恶意输入和 worker OOM | 进程隔离、显式复杂度拒绝或替换解析路径 |
| 新 DMARC 规范库支持不完整 | M6 新规范 fixture | 锁定已验证版本或补适配；公开限制，延后生产门槛 |
| VPS 无法直接投递 | 部署前查端口/PTR，M8 真互通 | L1 先用固定中继；不把 L1 当 L2 完成 |
| 2 GiB 机器总内存不足 | M7 计量所有服务 | 降并发/缓存或提高明确硬件基线 |
| 单机故障不可服务 | M7 恢复演练 | 明确 RTO；需要 HA 时另做复制设计 |

设计更改采用 ADR。缩减功能可以换取更早的受限发布，但必须同步修改能力表、配置校验、教程与对外声明。
