# 实现计划与验收矩阵

## 1. 当前状态与推进原则

2026-09-22：设计文档已先提交，Rust 实现推进至 0.7.0 / M4.1。已有环回 SMTP、存储恢复、身份/TLS、三个入口、本地交付及持久队列基础，见[本阶段教程](17-m4-durable-queue.md)。尚无网络外发或生产发布包；当前支持子集不代表完整 RFC 一致性。

阶段完成的含义是：代码、测试、教程、运维接口和验证证据同时满足退出条件。M1 本地存储、M2 身份/TLS 及 M3.1–M3.3 的 L0 子步骤已验收；最新两平台干净检出、有限 TLS/认证压力与存储故障回归见 [M3.3 报告](../reports/m3.3/validation.md)。这不等于生产发布，也不替代物理存储栈、真实负载与长时间验收。M0 仍有待补项，M3 的生产兼容缺口继续跟踪，M4–M8 尚未完成。

单人参考工作量约 20–36 人周：协议互通与故障验证存在较大不确定性，不能用该估计承诺日期。获得第一个实验收发闭环可以更早，但不等于生产发布。

0.3.1 为复查修复：取消生命周期、管理帧大小与有界性能优化，见[修复教程](13-cancellation-and-bounds.md)。M3.3 补上有限 TLS/认证混合实验；大存量启动/GC 扫描及真实持续负载仍待生产验收。

## 5. 测试层次与证据

## 7. L2 完整目标门槛

在 L1 基础上：M8 完成；直接 MX 路由、Null MX、失败分类、MTA-STS、DNS/SSRF、TLS 兼容策略均验证；至少两个独立外部服务双向互通；PTR、DKIM、SPF、DMARC 实际通过；队列积压、IP 信誉和政策拒绝有真实运维路径。

低信誉 IP、供应商封端口或域策略不匹配会影响投递，不能由软件质量声明覆盖。保留经过验证的中继作为管理员主动切换选项，绝不自动改变信任或加密政策。

## 8. 风险登记

| 风险 | 早期验证 | 失败时的处理 |
| --- | --- | --- |
| IMAP 完整实现工期被低估 | M0 literal spike，M5 条款矩阵 | 缩减可选扩展，不能冒充 rev1 核心已完整 |
| 磁盘同步决定吞吐上限 | M1 测 fsync 与混合读写 | 优化索引/小批提交或升级磁盘，不牺牲耐久性 |
| MIME 库分配不可控 | M0 恶意输入和 worker OOM | 进程隔离、显式复杂度拒绝或替换解析路径 |
| 新 DMARC 规范库支持不完整 | M6 新规范 fixture | 锁定已验证版本或补适配；公开限制，延后生产门槛 |
| VPS 无法直接投递 | 部署前查端口/PTR，M8 真互通 | L1 先用固定中继；不把 L1 当 L2 完成 |
| 2 GiB 机器总内存不足 | M7 计量所有服务 | 降并发/缓存或提高明确硬件基线 |
| 单机故障不可服务 | M7 恢复演练 | 明确 RTO；需要 HA 时另做复制设计 |

设计更改采用 ADR。缩减功能可以换取更早的受限发布，但必须同步修改能力表、配置校验、教程与对外声明。
