# M4.2 验证记录：固定上游 TLS 与原子混合提交

版本 0.8.0，schema 3。当前为待最终 CI 归档的工作记录；本地已运行的结果不替代干净检出与 Linux 实验。教程与复现入口见[第 18 章](../../docs/18-m4-smtp-relay.md)。

本轮实现真实单次 SMTP 尝试、验证证书的隐式 TLS/STARTTLS、AUTH PLAIN、后台队列执行、本地/远端混合接受，以及提交 Bcc 过滤和共享 blob 的出站投影。全部网络实验只向自建环回对端发送合成内容。

## 验证范围

- Rust：混合接受的提交前后故障、配额回滚、事务内撤销授权、幂等重放；远端 local-part 大小写；正文任意分块、EOF/格式失败不发结束点；实际网络取消及阻塞读取保护实例锁。
- 独立 Python 上游：24 个 TCP/TLS 单次场景，5 组完整队列与提交检查；包括真实发送过程中强杀进程、重启后 uncertain 不自动重发。
- 原有 SMTP、TLS/认证、STARTTLS、输入契约、48 行拒绝中继矩阵、队列八个强杀边界全部继续运行。
- Linux 专属：单次 TLS 约 1 MiB/25 MiB 正文的 RSS/HWM 采样；原有收信压力、存储 QEMU 故障及磁盘满回归。

## 解释与限制

delivered 只表示配置的上游在最终 DATA 回复中接受责任，不代表最终收件箱已收到。failed 仍未生成 DSN；到期/损坏/不兼容会保留责任并 hold，不自动删除正文。BODY 后未知结果进入 uncertain。

新的真实网络强杀测试属于进程故障，不是整机掉电。旧 QEMU 回归验证基础持久化，不能据此声称已覆盖每一个中继网络/磁盘组合故障。

首轮 Linux CI 的真实强杀检查暴露了恢复步骤缺口：Unix 管理 socket 遗留时，服务按既有策略拒绝覆盖路径。实验现已在确认子进程退出并核对 inode/所有者/私有目录后，显式清理自己创建的 socket。Linux 的强杀恢复仍需管理员执行这一操作，不能称为无人值守恢复；步骤与原因见第 18 章。Windows 没有这个 Unix 路径。

单次发送的内存采样只包括 Rust 探针，排除 Python 上游、队列、存储和 Argon2。采样峰值是观察下界，不能证明完整服务资源上界。连接复用、大队列公平性、固定上游共享退避和长期持续负载尚待验证。

本轮没有增加第三方依赖；完整 RustSec 公告刷新未重新执行。当前仍为 L0，生产启动被拒绝；没有 IMAP、DSN、域认证、反垃圾与公网真实互通。
