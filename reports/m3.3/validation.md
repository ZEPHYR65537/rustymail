# M3.3 验证记录：输入契约与资源恢复

版本 0.6.0，L0 环回实验。本记录随功能提交先登记验收范围；两平台干净检出、Linux release 压力与存储故障实验完成后补入实际提交号、CI 链接及原始数据。在证据归档前，不将待执行项目记为通过。

## 交付范围

MAIL 保留 BODY 模式并检查 EHLO 协商；SIZE 验证 1–20 位十进制，大整数返回大小限制错误；独立命令长度预算；收件人上限处正确去重；HELP/VRFY 不改变信封；DATA 编码、framing、头部、超限、超时和暂存失败有明确分类。默认 7BIT 与 ASCII 头部策略比 0.5.0 严格，旧客户端示例已更新。

没有修改数据库 schema、已存储 blob 或默认部署参数，没有增加第三方运行时依赖。教程、完整支持子集契约、能力矩阵和生产兼容缺口见[第 16 章](../../docs/16-m3-input-contract.md)。

## 验证入口

- Rust：既有存储/TLS/身份/TCP 测试，加五项参数、状态序列、去重和分片测试。
- 独立客户端：原 SMTP、M2、M3.1、M3.2 回归；M3.3 八组契约检查，包括 48 行角色/发件人/收件人矩阵。
- 压力：连接与握手饱和、12 轮 DATA 取消、三个入口 120 封投递与 40 个畸形连接；Linux 额外记录 RSS 峰值和描述符恢复。
- 存储：沿用 11 个 Linux VM 中止位置及两种实际 ENOSPC，不以协议检查替代持久化验收。
- 文档：链接、代码块、配置附件与 SQL 草案检查。

此版本仍非生产服务器。有限分片/状态枚举不等于完整 fuzz 或形式化证明；短压力不等于长时间 soak；回归上限不是生产内存承诺；QEMU 中止不等于物理磁盘掉电。

本地 Windows 已通过格式、严格 Clippy、61 项 Rust 测试、全部历史独立客户端回归、M3.3 八组检查和四组压力行为实验。此时为有修改的工作区验证；Linux 资源测量和干净检出的结果待 CI 归档。
